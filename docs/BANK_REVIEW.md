## Checks performed

- Every record contains a prompt, model answer, marks and marking guidance.
- All IDs and normalized prompt hashes are unique.
- All labels and MCQ answer mappings pass structural validation.
- Short-answer explanations were checked for Python semantics, including negative floor division, shallow copies, immutable strings, set order, file truncation and exception specificity.
- All eight coding model answers were exercised using trusted local fixtures, including empty inputs, palindrome case sensitivity, repeated/negative even numbers, Fibonacci boundaries, missing files, blank lines, conversion failures and append preservation.
- Student-facing wording specifies assumptions when ambiguity would affect an answer.

## Remaining academic review

Ask the instructor to assess wording, marks, difficulty estimates, time estimates and syllabus fit before using questions in a real assessment. `demo_reviewed` is a distinct database status. Do not automatically turn all sample records into approved records.

Difficulty is estimated for a beginner cohort, not measured using student scores. In this compact fixture, coding items were labelled Hard for demonstration; the software does not infer difficulty from question type. Future bank expansion should include multiple difficulty levels within the same type.
